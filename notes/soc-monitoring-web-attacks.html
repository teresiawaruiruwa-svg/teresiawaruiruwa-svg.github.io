TECHNICAL NOTE · SOC OPERATIONS

Monitoring web attack patterns

A concise field note on turning suspicious web request patterns into reviewable SOC signals.

WANJOHI TERESIA WARUIRUFIELD NOTE · DERIVED FROM FEATURED ARTICLE

Purpose

This note extracts the monitoring ideas from the accompanying OWASP article into a compact analyst reference. These patterns are starting points for detection engineering, not universal thresholds or proof of compromise.

1. Repeated authentication failures

Signal: a high rate of HTTP 401 responses associated with one source IP.

Example threshold: more than ten 401 responses within one minute, grouped by source IP.

Analyst checks:

  • Review whether failures target one account or many accounts.
  • Correlate with successful logins, MFA events and session creation.
  • Check whether the source is expected infrastructure, a proxy or a known scanner.

2. Directory and content discovery

Signal: unusually high volumes of 404 responses from one source, especially requests for common administrative, configuration or backup paths.

Example threshold: more than fifty 404 responses in ten seconds, subject to tuning for the application baseline.

Analyst checks:

  • Review request paths, user-agent values and request cadence.
  • Compare activity across virtual hosts and application endpoints.
  • Determine whether the activity is an approved vulnerability scan.

3. Injection and execution probes

Signal: request parameters or bodies containing SQL syntax patterns, encoded template delimiters or process-execution references.

Analyst checks:

  • Preserve the raw request and relevant WAF or application logs.
  • Check response codes, response sizes and follow-on requests.
  • Correlate with application errors, unusual child processes and outbound connections.

Response workflow

  1. Validate: distinguish malicious activity from legitimate testing, scanners and application behaviour.
  2. Scope: identify affected accounts, endpoints, hosts and time range.
  3. Contain: apply proportionate controls when evidence supports it, following incident procedures.
  4. Preserve: retain relevant logs and forensic evidence.
  5. Improve: tune detection logic and document false positives and gaps.
Implementation note

Thresholds should be baselined against normal traffic. An alert should initiate investigation; a single matching request or status code does not establish that an application has been compromised.
